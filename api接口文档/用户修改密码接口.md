# 用户修改密码接口文档

## 基本信息

- **接口标识**: `USER_CHANGE_PASSWORD`
- **请求路径**: `POST /api/users/change-password`
- **接口描述**: 用户通过JWT令牌认证后，输入原密码和新密码来修改密码
- **认证要求**: 需要JWT令牌认证
- **适用业务单元**: 用户密码管理

## 请求参数

### 请求头
```
Authorization: Bearer <JWT_TOKEN>
Content-Type: application/json
```

### 请求体
```typescript
interface UserChangePasswordRequest {
  oldPassword: string;     // 原密码，必填
  newPassword: string;     // 新密码，8-32字符，必填
  confirmPassword: string; // 确认新密码，必须与newPassword一致，必填
}
```

### 参数验证规则
```json
{
  "oldPassword": {
    "required": true,
    "type": "string",
    "message": "原密码不能为空"
  },
  "newPassword": {
    "required": true,
    "type": "string",
    "minLength": 8,
    "maxLength": 32,
    "message": "新密码长度必须在8-32字符之间"
  },
  "confirmPassword": {
    "required": true,
    "type": "string",
    "custom": "mustMatchNewPassword",
    "message": "确认新密码必须与新密码一致"
  }
}
```

## 业务逻辑说明

### 密码修改流程
1. **身份验证**: 验证JWT令牌的有效性，获取用户ID
2. **参数验证**: 验证新密码和确认密码是否一致
3. **用户查询**: 根据用户ID查询用户信息
4. **原密码验证**: 验证用户输入的原密码是否正确
5. **新密码检查**: 确保新密码与原密码不相同
6. **密码更新**: 对新密码进行加密并更新到数据库
7. **返回结果**: 返回修改成功或失败的响应

### 安全机制
- **JWT认证**: 确保只有已登录用户才能修改密码
- **原密码验证**: 防止未授权的密码修改
- **密码加密**: 使用BCrypt对新密码进行加密存储
- **重复密码检查**: 防止用户设置与当前密码相同的新密码

## 调试说明

### 重要提示
- **JWT令牌格式**: 必须是完整有效的JWT格式（包含两个点分隔符）
- **Authorization头部**: 必须以"Bearer "开头，后跟完整的JWT令牌
- **令牌有效性**: 确保令牌没有过期且格式正确
- **常见错误**: 如果出现"JWT strings must contain exactly 2 period characters"错误，说明令牌格式不正确

## 注意事项

1. **令牌有效性**: 确保JWT令牌未过期且有效
2. **密码强度**: 建议前端对新密码进行强度验证
3. **频率限制**: 建议对密码修改操作进行频率限制，防止恶意攻击
4. **日志记录**: 系统会记录密码修改操作的日志，便于安全审计
5. **会话管理**: 密码修改成功后，建议用户重新登录以确保安全性
